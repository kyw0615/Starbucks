# 스케줄 달력

근무표 텍스트를 붙여넣으면 **달력**으로 보여주고, **배경화면 이미지**로도 저장할 수 있습니다.
접속한 기기의 해상도를 자동으로 감지해 딱 맞는 크기로 저장합니다.

## 사용법

### 1. 스케줄 붙여넣기

근무표를 그대로 복사해서 붙여넣으면 됩니다. 줄바꿈·탭·공백 어떤 구분이든 인식합니다.

```
출근
퇴근
근태코드
07/13(월)
10:30
17:30
정상
07/14(화)
15:30
21:00
정상
07/15(수)
정규휴일
07/17(금)
법정휴일
07/18(토)
휴가
07/19(일)
09:00
18:00
연장근무
```

날짜(`MM/DD`) → 출근 시각 → 퇴근 시각 → 근태코드 순서로 읽습니다.
시간 없이 근태코드만 있으면 휴무로 처리합니다.

### 2. 주간 스케줄 추가

새 주간 근무표가 나오면 **＋ 이번 주 추가** 칸에 붙여넣고 버튼만 누르면 맨 아래에 이어붙습니다.
같은 날짜가 이미 있으면 **나중에 입력한 값**으로 덮어씁니다 (오타 수정 시 그대로 다시 붙여넣으면 됨).

### 3. 이미지 저장

| 버튼 | 크기 | 용도 |
|---|---|---|
| **전체화면** | 기기 해상도 그대로 | 배경화면으로 바로 설정 |
| **단축어용** | 가로 1.4배 | iOS 단축어 자동화 — 배경화면 확대 시 잘림 방지 |

모바일에서는 **공유 시트**가 열립니다. `이미지 저장`을 누르면 사진첩에 바로 들어갑니다.
(iOS Safari는 일반 다운로드가 '파일' 앱으로 가서 사진첩에 안 들어가기 때문입니다.)
데스크탑 등 공유를 지원하지 않는 환경에서는 자동으로 일반 다운로드로 처리됩니다.

## 근태코드

근태코드는 **따로 등록할 필요가 없습니다.** 출퇴근 시간이 있는지로만 판단합니다.

| 조건 | 표시 |
|---|---|
| 출퇴근 시간 **있음** | 출근–퇴근 시각 + 근무시간 |
| 출퇴근 시간 있음 + 코드에 `법정휴일` 포함 | 위와 같음 + **날짜·칸 빨강** |
| 출퇴근 시간 **없음** | 근태코드를 **그대로** 표기 (회색) |
| 출퇴근 시간 없음 + 코드에 `휴가`/`연차` 포함 | 😎 (칸 중앙) |

`예비군`, `대체근무`, `경조휴가` 같은 처음 보는 코드도 그대로 동작합니다.

## 표시 규칙

- 달력은 **오늘 기준 1주 전부터 5주(35일)** 를 고정으로 보여줍니다. 일요일마다 한 주씩 자동으로 넘어갑니다.
- 근무시간은 **하루 30분 휴게시간을 뺀 값**입니다.
- 두 달에 걸친 일정도 한 화면에 이어서 표시됩니다.

## 친구와 실시간 공유 (선택)

같은 그룹에 들어간 사람끼리 스케줄이 **자동으로 동기화**됩니다. 한 번 가입해 두면
앱을 열 때마다 알아서 다시 붙으므로, 이후에는 아무 조작도 필요 없습니다.

설정하지 않아도 앱은 지금처럼 이 기기에만 저장하는 방식으로 잘 동작합니다.

### 1. Firebase 프로젝트 만들기

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 프로젝트 생성 (무료 Spark 요금제)
2. **빌드 → Realtime Database** → 데이터베이스 만들기 → 위치는 `asia-southeast1` 권장
3. **빌드 → Authentication** → 시작하기 → **익명(Anonymous)** 로그인 사용 설정
   - 기기마다 고정 ID를 부여하기 위해 필요합니다. 이메일·비밀번호는 쓰지 않습니다.

### 2. 접근 규칙 붙여넣기

**Realtime Database → 규칙** 탭에 저장소 루트의
[`database.rules.json`](database.rules.json) 내용을 그대로 붙여넣고 게시합니다.

이 규칙이 실제 접근 제어를 담당합니다.

- 그룹 멤버가 아니면 그 그룹의 **어떤 값도 읽을 수 없습니다.**
- 새로 들어오려면 **방 코드가 서버에서 대조**되어야 합니다. 코드가 틀리면 규칙이 거부합니다.
- 이미 등록된 멤버의 기록 갱신에는 코드 대조를 요구하지 않습니다.
  덕분에 코드를 재발급해도 남아 있는 멤버의 동기화는 끊기지 않습니다.

### 보안 모델과 한계

**멤버는 방 코드를 읽을 수 있습니다.** Realtime Database는 상위 경로에서 준 읽기 권한을
하위에서 회수할 수 없어, 그룹 내용을 멤버에게 열어 준 이상 `secret/code` 도 함께 읽힙니다.
이 앱은 이 점을 감추려 하지 않고 **"멤버는 코드를 안다"를 전제로** 설계했습니다.

여기서 따라오는 규칙이 하나 있습니다 — **내보내기만으로는 축출이 되지 않습니다.**
내보낸 사람은 저장해 둔 코드로 다시 등록할 수 있기 때문입니다.
그래서 **멤버를 내보내면 초대 코드가 자동으로 함께 재발급**되고,
화면에 "새 초대 코드가 발급되었습니다" 안내와 재공유 버튼이 뜹니다.

재발급 후에는 **남은 멤버에게 새 코드를 다시 알려 주세요.** 기존 멤버는 그대로 동기화되지만,
그중 누군가 브라우저 저장소를 지워 기기 ID가 바뀌면 신규 가입 경로를 타므로 새 코드가 필요합니다.
(그룹 관리 화면을 열면 현재 코드를 자동으로 받아 와 표시를 최신으로 맞춥니다.)

코드가 새어 나간 것 같으면 **[초대 코드 새로 발급]** 으로 언제든 직접 갈아끼울 수 있습니다.

### 3. 설정값 넣기

Firebase 콘솔 → **프로젝트 설정 → 내 앱(웹)** 에서 설정값을 복사해
[`src/firebaseConfig.ts`](src/firebaseConfig.ts) 에 채워 넣고 푸시하면 배포됩니다.

```ts
export const firebaseConfig = {
  apiKey: 'AIza...',
  authDomain: '<프로젝트ID>.firebaseapp.com',
  databaseURL: 'https://<프로젝트ID>-default-rtdb.asia-southeast1.firebasedatabase.app',
  projectId: '<프로젝트ID>',
  appId: '1:...:web:...',
};
```

> 이 값들은 **공개되어도 되는 정보**입니다. Firebase 웹 설정은 원래 브라우저로 내려가며,
> 실제 보안은 위의 데이터베이스 규칙이 담당합니다.

### 4. 사용법

앱 최하단 **그룹 관리** 버튼에서:

| 기능 | 설명 |
|---|---|
| 그룹 만들기 | 초대 코드가 생성됩니다. 이 코드를 아는 사람만 들어올 수 있습니다. |
| 그룹 들어가기 | 받은 초대 코드를 붙여넣습니다. |
| 그룹 나가기 | 동기화가 멈춥니다. 이 기기의 스케줄은 그대로 남습니다. |
| 멤버 내보내기 | 다른 멤버를 제거하고 초대 코드를 함께 재발급합니다. |
| 초대 코드 재발급 | 예전 코드를 무효화합니다. 남은 멤버의 동기화는 유지됩니다. |

초대 코드는 `그룹ID(12자)-방코드(6자)` 형태입니다. 대소문자·하이픈·공백은 자동으로 정리되며,
헷갈리기 쉬운 `O/0`, `I/1` 은 애초에 쓰이지 않습니다.

동시에 수정하면 **나중에 저장된 쪽이 반영**됩니다 (파서의 중복 처리 원칙과 동일).

## 데이터 저장

입력한 스케줄은 브라우저의 `localStorage`에 자동 저장됩니다.
그룹에 가입하지 않으면 서버로 전송되지 않으므로, 여러 사람이 같은 주소를 써도
각자의 데이터는 서로 보이지 않습니다.

> ⚠️ 저장은 **브라우저·기기별로 분리**됩니다. 기기를 바꾸거나 브라우저 데이터를 지우면 초기화됩니다.

```bash

```

## 배포 (GitHub Pages)

`main` 브랜치에 푸시하면 [GitHub Actions](.github/workflows/deploy.yml)가 자동으로 빌드·배포합니다.

최초 1회 설정이 필요합니다:

1. GitHub 리포지토리 → **Settings** → **Pages**
2. **Source** 를 **GitHub Actions** 로 변경
3. `main` 에 푸시

배포 주소는 `https://<사용자명>.github.io/<리포지토리명>/` 입니다.
`base` 경로는 리포지토리 이름으로 자동 설정되므로 별도 수정이 필요 없습니다.
